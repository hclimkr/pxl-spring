# PXL Spring 0.9.1

Imports now accept a Spring `Resource` as well as a multipart upload, so the paths that are not HTTP — a batch job, a seed loader, a test — have an entry point of their own. The contributing guide also states what the repository takes: issue reports and suggestions, reviewed and applied by the maintainer. Built against [PXL](https://github.com/hclimkr/pxl) 0.9.3, up from 0.9.2.

Pre-1.0 release carrying a **breaking rename from the core**: every method of this library is unchanged, but `exportFileFormat` becomes `exportExcelEngine` and takes the new `PxlExcelEngine`, which reaches the DTOs and option objects you write — see the second highlight.

## Highlights

  - **Import from a `Resource`**: `fromResource(...)` on `importExcel()`, and `fromResource(...)` / `fromResources(...)` on `importCsv()` — for a file on disk (`FileSystemResource`), a packaged one (`ClassPathResource`), or anything else behind Spring's `Resource` abstraction. Everything else is unchanged: the same extension validation, the same name derivation, the same options
  - **`exportExcelEngine` replaces `exportFileFormat`** *(breaking, from the core)*: `@PxlWorkbook(exportExcelEngine = ...)` and `PxlExportWorkbookOption.exportExcelEngine` take a `PxlExcelEngine` (`HSSF` / `XSSF` / `SXSSF`), the POI implementation that writes the workbook, while `PxlFileFormat` keeps physical formats only (`XLS` / `XLSX` / `CSV`). To migrate, rename the attribute and swap the enum: `PxlFileFormat.HSSF` → `PxlExcelEngine.HSSF`. Downloads are unaffected in behavior — the response extension and content type still come from `PxlFileFormat`, which the exporters now reach through the engine, and the raw `poiWorkbook(...)` form still reads it off the workbook itself
  - **Contributing policy**: `CONTRIBUTING.md` / `CONTRIBUTING_ko.md` state that the repository accepts issue reports and suggestions only — pull requests are not accepted, and the maintainer reviews each issue and makes the change
